# Agent Instructions

## General

- Inspect the relevant existing code before making changes.
- Follow existing repository conventions.
- Prefer the smallest change that fully solves the requested problem.
- Do not perform unrelated refactors.
- Do not rewrite working code merely to use a different style.

## Package Management

Use the package manager configured by this repository.

## Dependencies

Prefer existing platform and project capabilities before adding a dependency.

Do not introduce a new dependency, framework, language, or build tool unless
it provides a clear benefit for the requested change.

## Generated Data

Treat source files as the source of truth.

Do not manually edit generated metadata or generated files when they can be
regenerated by the build pipeline.

When changing a generated data schema, inspect its consumers before modifying
field names or semantics.

## Validation

Use the validation commands defined by the repository.

Run the narrowest relevant check first.

For changes affecting the build pipeline or project structure, verify that the
project builds successfully before considering the task complete.

If an existing check already fails for reasons unrelated to the change, report
it instead of silently modifying unrelated code.

## Communication

Keep completion summaries concise.

Report:

- what changed
- what was validated
- unresolved problems, if any
